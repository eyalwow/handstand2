## Findings and changes

1. **Reproduced model initialization failure in WebKit.** With the unchanged PR26 classic Worker and the genuine pinned MediaPipe 0.10.14 library/model, Chromium initializes and infers; Windows Playwright WebKit 26.5 throws `Can't find variable: document` at `Qa` in `vision_bundle.mjs:1:74812`. Import and FilesetResolver succeed; PoseLandmarker creation fails. That Worker lacks OffscreenCanvas, so MediaPipe falls back to a DOM canvas in a context without document. This is a proven compatibility defect, not proof of the exact user's phone/browser/version, which is unavailable.
2. Worker now detects the missing canvas and emits a specific capability code. The facade falls back **only for that capability** to an explicit HTML canvas and local CPU model. On capable Workers an explicit OffscreenCanvas also avoids MediaPipe's implicit canvas/user-agent heuristic. Network/import/WASM failures remain errors rather than silently selecting another backend. Model-load cancellation/timeout closes any late-created compatibility model. Main-thread compatibility yields between synchronous calls; an individual call cannot be interrupted mid-inference and can briefly delay UI.
3. **Confirmed nondeterministic sampling in old source.** Playback speed adapts to inference cost; callback arrival picks rounded indices and leaves variable holes. The seek fallback first probes sparsely, then rewinds/reuses cached frames while the VIDEO model retains tracking state. Successful uploads also reused that model across different files. These are causal mechanisms in source, not a recovered trace of the user's three earlier grades.
4. Replaced both analysis sampling paths with exhaustive chronological seeks at fixed 10 Hz (`0.05 + index/10`), original source-time model timestamps, CPU delegate and a fresh model for every upload, closed in all completion paths. No sparse warmup, playback-speed adaptation or previous-upload tracker state. Scoring functions, weights, confidence/coverage gates and numeric thresholds are unchanged. Timeout budget increases to match exhaustive seeking: 90 seconds minimum, six times source duration, eight minutes maximum. This deliberately prioritizes repeatability over playback-speed throughput.
5. Seek/metadata listeners are installed before operations, cleaned up after completion, cancellation and timeout. A timeout rejects instead of silently capturing an old frame. WebKit can expose a media clock different from the seek target after `seeked`; readiness therefore requires that event, non-seeking state and decoded data rather than exact currentTime equality. Local diagnostics record requested and exposed media times, metrics, phases and final score. They are browser events only; no video, pose or diagnostic is uploaded. The test runner hashes its input outside the app to avoid copying large iPhone videos into memory just for a checksum.
6. New history entries carry `v3-fixed-*` sampling identifiers. Existing `v2-*` entries are preserved and displayed; comparisons require matching identifiers. No storage migration, deletion or entitlement change.
7. Upload replaces the rectangular framing illustration with the **existing licensed photograph**, concise instructions, one selector, percent progress, accessible status and retry. The newly mentioned AI male-athlete photograph was not supplied, so it was not assessed or generated. Source remains Isabella Mendes/Pexels photo 348489, documented in assets/photography/README.md; photograph illustrates the context, not a user result or validated technique demonstration.

## Reproduce repeated-file checks

Use Node 22+ and Playwright with installed browsers. Serve `vercel-app/` locally or use the authorized Preview. The script changes no app source and mocks no inference/network response:

```sh
node scripts/verify-video-repeatability.mjs --url http://localhost:8000/#analyze --video /path/to/clip.mp4 --browser chromium --output /tmp/repeated-video.json
```

Set `PLAYWRIGHT_MODULE` to an existing Playwright package when it is not locally installed. Default is three runs. The report includes the file checksum, requested/exposed times, raw measured metrics, score, timings, page errors and outbound POST URLs. It fails if a real reliable score is missing, diagnostics differ or a POST occurs. No test clip, credential, original user media or environment file should be committed. `--browser webkit` must pass the same standard; the Windows limitation is not silently bypassed by this committed test.
