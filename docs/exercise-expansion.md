## Developer-only gate tracing

`analyzeFrontLever(input, {onDebug: event => { /* inspect privately */ }})` opts into in-memory sample and summary events. The application never supplies this second argument. No debug data is attached to the result, rendered, persisted, printed, or uploaded by the analyzer. Do not wire this callback to public telemetry or commit real poses, footage, identifiers, or diagnostic dumps. Existing result/history contracts and provisional gates are unchanged.

Sample events report the source time/index, both sides' joint visibility and usability issues, projected trunk tilt, elbow/shoulder/hip/knee angles, ankle deviation in torso lengths, shoulder separation ratio and overhead-wrist distance. Null means unavailable, never inferred extension. `visibility` is the existing Worker's `v` value (MediaPipe visibility); it is not a separate calibrated confidence or presence score. `coreConfidence` is the minimum visibility of the selected shoulder/elbow/wrist/hip. Angles use usable joints only; rejected-side measurements are diagnostic projections, not accepted observations.

`reasons` records the actual rejection stage: missing pose, core quality, short torso, side-view separation, geometry, missing previous core, side switch, timing gap or motion. Earlier rejection stops later gates; an absent reason does not mean a downstream gate passed. Geometry can report several simultaneous failures. Summary `rejectionCounts` counts all recorded reasons; `firstRejectionCounts` counts only the first per rejected sample and avoids double counting. Preflight failures emit a summary with zero evaluated samples and the input/selection/camera/timing reason.

`candidateSeconds`/`candidateSamples` track the uninterrupted run of stability-passing samples ending at that sample; a singleton is zero seconds. Summary reports their maxima even when no hold qualifies. The existing hold still requires at least 1.5 seconds, 15 samples and gaps no larger than 0.16 seconds. A stable sample with empty reasons can belong to an insufficiently long candidate. Optional leg metrics never gate a hold. Tracing alone does not validate the selected variation or body support.

Run `node --test tests/*.test.*` for the full suite. Focused debug tests assert opt-in result equivalence and input immutability, geometry/visibility, staged rejection reasons, timing and candidate boundaries. Real-footage diagnostics belong only in private local artifacts. Do not loosen thresholds from a single oblique recording: a wider camera gate can admit frontal/foreshortened or supported horizontal poses, and a wider motion gate can admit swings.
